# Brief 04: Planning and Spec-Driven Development

## Mission
Upgrade the flow from idea to spec to plan to tasks. The flow must stay **Linear-native** and keep the Memory OS spec and constitution model.

## Key questions
1. What are the 2026 spec-driven development frameworks, and how do they compare with Memory OS `spec init` and `analyze`?
2. What is the best practice for agent-written plans? Consider plan mode, requirement IDs, acceptance criteria as tests, and the right plan granularity for each model tier.
3. Task decomposition: how should a spec map onto Linear projects, issues, and sub-issues, and onto 12-step scores? Can automatic scoring be trusted?
4. Clarification loops: when should an agent stop and ask? Look at structured question templates.
5. Estimating and tracking agent effort versus human effort.
6. How should planning artifacts be versioned in Git and kept in sync with Linear without creating two sources of truth?

## Seed candidates (verify)
GitHub Spec Kit, Kiro specs, the BMAD Method, Task Master, OpenSpec, Agent OS, Claude Code plan mode, Linear project templates, and the Linear MCP.

## Special deliverable
A **canonical planning workflow**: which artifact lives where (Git or Linear), who writes it (which agent or human), and which gate each step must pass.
